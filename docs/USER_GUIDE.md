# TJudge — руководство пользователя

Турнирная платформа для теории игр: команды загружают программы-стратегии, программы играют друг против друга, система считает ELO и ведёт лидерборды.

Доступ: `https://<ваш-домен>` (локально `http://localhost:8080`).

Схема участия: регистрация → команда → турнир → по одной программе на каждую игру турнира → система гоняет матчи и обновляет рейтинг → положение видно в лидерборде турнира и кросс-игровом рейтинге.

## Регистрация и вход

Регистрация — `/register` (или `/login` → «Регистрация»):

- Имя пользователя — латиница, без пробелов, уникальное.
- Email — для уведомлений.
- Пароль — минимум 8 символов.

После регистрации вы сразу авторизованы.

Вход — `/login`. JWT хранится в localStorage: 24 часа по умолчанию, до 7 дней с refresh-токеном. Выход через меню профиля — токен сразу попадает в blacklist. Смена имени, email, пароля — `/profile`.

## Команды

Команда — единица участия в турнире (одна программа на игру от команды). Размер команды задаёт админ турнира.

- Создать: на странице турнира «Создать команду» → название. Система выдаёт invite-код и ссылку-приглашение.
- Вступить: «Вступить в команду» → ввести код.
- Покинуть: `/teams/:id` → «Покинуть». Лидер сначала передаёт лидерство или распускает команду.

Создатель команды — лидер: исключает участников, переименовывает команду, удаляет её (пока турнир не начался).

## Турниры

`/tournaments` — список активных и завершённых турниров (название, статус, число участников).

`/tournaments/:id`:

- Описание, правила, список включённых игр.
- Кнопка «Присоединиться» (пока турнир принимает участников).
- Таблица лидеров — общий кросс-игровой рейтинг.
- Вкладка по каждой игре: своя таблица и список матчей.

Жизненный цикл:

1. Админ создаёт турнир, добавляет игры.
2. Команды регистрируются и загружают программы.
3. Админ запускает турнир — приём команд закрывается.
4. Планировщик формирует пары round-robin, матчи уходят в очередь воркерам.
5. Рейтинг обновляется в реальном времени по мере готовности результатов (WebSocket).
6. После всех запланированных раундов турнир помечается завершённым.

## Программы-стратегии

- Один файл или архив.
- Язык любой — важна исполняемость в изолированном Docker-контейнере `tjudge-cli`.
- Лимиты по умолчанию: 512 МБ памяти, 60 секунд на матч, сеть отключена.
- Протокол: ввод-вывод текстом через stdin/stdout, формат описан в правилах конкретной игры.

Загрузка со страницы команды (`/tournaments/:id/my-team`): выбрать игру → загрузить файл → указать язык (или «auto») и точку входа при необходимости → «Загрузить». Сервер проверяет размер и формат, делает базовый статический анализ и ставит программу в очередь на компиляцию.

Версии: хранятся все загруженные версии команды по каждой игре, актуальна — последняя успешно скомпилированная. Старые остаются в истории, их можно скачать.

Статус `error` (детали на `/programs/:id`) — типичные причины:

- Синтаксическая ошибка.
- Программа не читает stdin или не печатает ответ в stdout.
- Превышены лимиты памяти или времени.
- Попытка сетевого доступа (запрещена).

После исправления загрузите новую версию.

## Лидерборд и ELO

У каждой программы свой рейтинг по каждой игре, старт — 1500. После матча оба рейтинга корректируются по формуле ELO (K-фактор задан в конфиге игры).

- Кросс-игровой лидерборд турнира — сумма (или взвешенная сумма) ELO по играм.
- Лидерборд конкретной игры — только её рейтинг.
- Глобальный рейтинг вне турниров — опционально, на главной.

Страница турнира подписана на WebSocket `/api/v1/ws/tournaments/:id` и сразу показывает новые результаты. Чтение публичных лидербордов авторизации не требует, WebSocket-подключение — требует.

## Встроенные игры

Точные параметры (раунды, множители, лимиты) задаёт админ при добавлении игры в турнир.

**Дилемма заключённого (`dilemma`).** Два игрока одновременно выбирают C (сотрудничать) или D (предать), N раундов. Программа читает историю раундов из stdin и печатает `C` или `D`. Побеждает большая сумма очков. Выплаты за раунд:

| Я \ Оппонент | C | D |
|---|---|---|
| C | 3, 3 | 0, 5 |
| D | 5, 0 | 1, 1 |

**Перетягивание каната (`tug_of_war`).** Две команды выставляют силы на флаг; чьё суммарное усилие больше — тот сдвинул канат. Общий ресурс усилий ограничен и распределяется по раундам.

**Дилемма путешественника (`travelers_dilemma`).** Двое независимо объявляют цену от 2 до 100. Оба получают меньшую из двух; назвавший меньшее число получает бонус, большее — штраф. Равновесие по Нэшу — 2.

**Общественное благо (`public_goods`).** N игроков вкладывают в общее благо; сумма умножается на множитель и делится поровну между всеми независимо от вклада. Задача о безбилетниках.

**Аукцион двойной цены (`dollar_auction`).** Второй по величине ставщик тоже платит свою ставку, но ничего не получает.

## Админская панель

Роль `admin` назначается через CLI: `make admin EMAIL=...`. Интерфейс — `/admin`.

- Турниры: создание, добавление игр, запуск, завершение, удаление.
- Ручной перезапуск матчей: `run-matches`, `run-game-matches`, `retry-matches`.
- Завершение/сброс раунда по игре внутри турнира.
- Авто-раунд: следующий раунд стартует, когда пул матчей исчерпан.
- Массовая загрузка программ команд по zip-архиву.
- Команды: дисквалификация, восстановление, удаление.
- Игры: добавление, редактирование, удаление (кроме встроенных).
- Audit-лог: `/admin` → «Audit».
- Очередь матчей: статистика, очистка, удаление невалидных записей.

Все админские действия пишутся в `audit_log` с привязкой к admin-пользователю.

## API

Справочник — `docs/openapi.yaml`; Swagger UI — `/swagger/` (требует admin-токен). Авторизация: `Authorization: Bearer <JWT>`.

Группы: `/api/v1/auth/*`, `/api/v1/tournaments/*`, `/api/v1/teams/*`, `/api/v1/programs/*`, `/api/v1/games/*`, `/api/v1/matches/*`, `/api/v1/ws/tournaments/:id`.

## Частые вопросы

**Почему программа в статусе `error`?** Детали на `/programs/:id`; причины — см. «Программы-стратегии». Локально воспроизводится запуском `tjudge-cli` в Docker с теми же лимитами.

**Как часто обновляется рейтинг?** Сразу после обработки матча воркером. Открытая страница получает обновление через WebSocket; иначе — ручной refresh.

**Можно ли загрузить новую версию во время турнира?** Да, пока раунд по этой игре не стартовал. Иначе версия попадёт в следующий раунд.

**Как скачать все программы команды?** Админ — на странице турнира `programs/download-zip`; обычный участник — со своей страницы команды.

**Куда писать о баге?** В GitHub issues репозитория. Приложите request-id из заголовка `X-Request-ID` — оператор найдёт контекст в логах.

## Добавление новой игры

Игра — это две части: исполнитель в [tjudge-cli](https://github.com/bmstu-itstech/tjudge-cli) (Rust) и плагин-метаданные в Go-сервере.

1. Поддержка в tjudge-cli: модуль `src/games/your_game.rs`, реализация trait `Game` (инициализация, итерации, подсчёт очков), регистрация типа игры в CLI-аргументах, пересборка Docker-образа `tjudge-cli`.
2. Регистрация GamePlugin в `internal/service/game/builtin.go` (внутри `RegisterBuiltinGames`):

```go
must(registry.Register(&GamePlugin{
    Name:              "your_game",     // совпадает с именем типа игры в tjudge-cli, [a-z0-9_]+
    DisplayName:       "Название игры", // отображаемое имя в UI (UTF-8)
    DefaultIterations: 100,             // итераций в матче по умолчанию
    ScoreMultiplier:   1.0,             // балансировка вклада игры в общий рейтинг
}))
```

`ScoreMultiplier` подбирается так, чтобы вклад игры в кросс-игровой рейтинг был сопоставим с Дилеммой заключённого (у `tug_of_war` — `10.0`, очки за раунд там 0 или 1; у `travelers_dilemma` — `0.05`; у `public_goods` — `0.1`).

3. Запись игры в БД: SQL-миграция seed с правилами по аналогии с `migrations/000015_seed_games.up.sql` либо `POST /api/v1/games` под админом (`name`, `display_name`, `rules` в Markdown — включайте протокол взаимодействия, формат ввода/вывода и ограничения; правила показываются участникам на странице игры).
4. Добавить игру к турниру: `POST /api/v1/tournaments/:id/games` (id игры в теле запроса; доступно админу или создателю турнира) — после этого участники загружают программы, игра входит в раунды.

Имя игры обязано совпадать в tjudge-cli и в Go-плагине — по нему система сопоставляет записи в БД с исполнителем.
