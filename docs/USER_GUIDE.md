# TJudge — руководство пользователя

Турнирная платформа для теории игр: команды загружают программы-стратегии, программы играют друг против друга, система считает очки и ведёт лидерборды.

Доступ: `https://<ваш-домен>` (локально `http://localhost:8080`).

Схема участия: регистрация → команда в турнире → турнир запущен → по программе на каждую игру турнира → раунды матчей → место в таблице игры и в общей таблице турнира.

## Регистрация и вход

Регистрация — на странице `/login`, вкладка «Регистрация»:

- Имя пользователя — 3–50 символов: латиница, цифры, `_` и `-`, уникальное.
- Email — корректный адрес, уникальный.
- Пароль — 8–128 символов, заглавные и строчные буквы и цифра.

Вход — `/login`, по имени пользователя или email. Сессия держится на паре токенов в localStorage: access живёт час и обновляется сам, refresh — неделю с последней активности. Выход через меню профиля отзывает refresh-токен. В `/profile` меняются имя, email и пароль (нужен текущий). После смены пароля остальные сессии разлогиниваются.

## Команды

Команда — единица участия в турнире: в одном турнире пользователь состоит в одной команде. Максимальный размер команды задаёт админ при создании турнира.

- Создать или вступить можно, пока турнир не запущен: на странице турнира «Участвовать» → «Создать новую команду» (название) или «Присоединиться к существующей» (код приглашения).
- Код и ссылку-приглашение `/join/<код>` видит только лидер: страница команды `/teams/:id` → «Пригласить участников». По ссылке достаточно нажать «Вступить».
- Создатель команды — лидер: переименовывает команду и исключает участников.
- Покинуть: `/teams/:id` → «Покинуть команду». Если уходит лидер, лидерство переходит к другому участнику. Уход последнего участника удаляет команду, но только пока турнир не запущен. Из команды завершённого турнира выйти нельзя. Удалить команду может только админ.

## Турниры

`/tournaments` — список турниров. Страница турнира `/tournaments/:id` — вкладки «Информация», «Таблица» (общий рейтинг команд), «Матчи» (по раундам), «Игры», «Команды». Страница игры турнира `/tournaments/:id/games/:gameId` — загрузка программы, таблица рейтинга игры, матчи, правила.

Жизненный цикл:

1. Админ создаёт турнир и добавляет игры.
2. Команды собираются, пока турнир в статусе pending.
3. Админ запускает турнир, после этого открывается загрузка программ.
4. Раунды запускает админ вручную или авто-раунд: новый раунд игры стартует, когда предыдущий доигран, прошёл заданный интервал и появились новые программы. В раунде каждая пара программ играет дважды, меняясь ролями первого и второго игрока.
5. Результаты и таблицы обновляются в реальном времени.
6. Админ завершает турнир, незавершённые матчи отменяются.

## Программы-стратегии

- Один файл исходного кода. Язык определяется по расширению: `.py`, `.c`, `.cpp`/`.cc`/`.cxx`, `.go`, `.rs`, `.java`, `.js`, `.rb`, `.php`, `.lua`. Размер — до 10 МБ.
- Протокол — строки через stdin/stdout. Формат, ограничения и пример сессии — в правилах игры на её странице. После каждой строки вывода нужен `flush`, на ход отводится 200 мс.
- Сети нет ни при сборке, ни в матче. Лимиты матча по умолчанию на обе программы вместе: одно ядро CPU, 512 МБ памяти, 60 секунд, `/tmp` 64 МБ. На каждую программу: до 48 процессов и потоков, файлы до 32 МБ. Собранная программа — до 32 МБ.
- Программы соперников работают под разными пользователями: прочитать код соперника или послать ему сигнал нельзя.

Загрузка: страница игры турнира → выбрать файл → загрузить. Загрузка открыта, пока турнир идёт. В ручном режиме она закрыта, пока идёт раунд любой игры турнира и после завершения раунда этой игры. С авто-раундом загрузка не блокируется, новая версия попадёт в следующий раунд. У команды до 100 версий на игру.

Статусы: `compiling` — сборка в песочнице (компилируемые языки собираются, для интерпретируемых проверяется синтаксис); `ready` — программа будет играть; `failed` — ошибка сборки, текст на странице игры. В раундах играет последняя `ready`-версия команды, пока её нет, команды нет в таблицах. Программы видны и скачиваются всей командой.

Если программа в матче падает, выводит недопустимый ход или не укладывается в лимиты, матч засчитывается сопернику. Текст ошибки матча целиком видят своя команда и админы.

## Таблицы и рейтинг

- **Таблица игры** — места по сумме очков программ команды во всех матчах этой игры; при равенстве выше больше побед, затем более ранняя загрузка.
- **Общая таблица турнира** — сумма очков по всем играм, очки каждой игры умножаются на её `score_multiplier`, чтобы вклад игр был сопоставим. Порядок при равенстве тот же.
- **ELO** — вспомогательный показатель: у каждой программы в турнире старт 1500, после матча пересчёт с K=32. На места не влияет, история видна на графике в таблице игры.

Сыгранными считаются завершённые матчи и форфейты. Страница турнира получает обновления через WebSocket `/api/v1/ws/tournaments/:id` (для залогиненных). Без WebSocket идущий турнир обновляется опросом. Читать таблицы можно без входа.

## Встроенные игры

Правила с таблицами очков и протоколом — на странице игры (`/games`). Число итераций в матче общее для всех игр (`EXECUTOR_DEFAULT_ITERATIONS`).

| Игра | Идентификатор | Суть | Множитель |
|------|---------------|------|-----------|
| Дилемма заключённого | `dilemma` | одновременный выбор `COOPERATE`/`DEFECT` | 1.0 |
| Перетягивание каната | `tug_of_war` | распределение запаса энергии по раундам | 10.0 |
| Дилемма путешественника | `travelers_dilemma` | заявка в диапазоне, меньшая получает бонус | 0.05 |
| Общественное благо | `public_goods` | вклад в общий пул, пул умножается и делится | 0.1 |
| Аукцион двойной цены | `dollar_auction` | поочерёдные ставки, платят оба | 1.0 |

## Админская панель

Роль `admin` выдаётся командой `make admin EMAIL=...` на сервере, после неё нужен перелогин. Интерфейс — `/admin`, вкладки:

- «Игры» — создание, правка правил, удаление.
- «Турниры» — создание, добавление игр, запуск турнира, запуск и сброс раундов, авто-раунд, завершение.
- «Программы» — программы турнира, скачивание по одной или всех архивом (.zip).
- «Система» — статус системы, очередь матчей (статистика, очистка с отменой ожидающих матчей, удаление невалидных записей), кнопки восстановления (зависшие матчи, компиляция, outbox, dead-letter).

Дисквалификация и восстановление команд — на странице турнира, вкладка «Команды». Дисквалификация возможна только в идущем турнире: сыгранные матчи команды удаляются вместе с их вкладом в ELO соперников, ожидающие отменяются. Восстановление снимает отметку, удалённые матчи не возвращаются. Перезапуск упавших матчей — кнопка «Перезапустить неудачные» на странице турнира. Админские действия пишутся в `audit_log`, журнал — `GET /api/v1/admin/audit` (в интерфейсе его нет).

## API

Справочник — [`docs/openapi.yaml`](openapi.yaml). Авторизация: `Authorization: Bearer <JWT>`, для WebSocket — сабпротокол `access_token.<jwt>`.

Группы: `/api/v1/auth/*`, `/api/v1/tournaments/*`, `/api/v1/teams/*`, `/api/v1/programs/*`, `/api/v1/games/*`, `/api/v1/matches/*`, `/api/v1/ws/tournaments/:id`, админские `/api/v1/system/*` и `/api/v1/admin/audit`.

## Частые вопросы

**Почему программа в статусе `failed`?** Текст ошибки сборки — на странице игры турнира. Типичные причины: синтаксическая ошибка, для C/C++ — предупреждение, которое GCC 14 считает ошибкой (например, неявное объявление функции), в Java-файле нет объявления `class`.

**Как часто обновляется таблица?** После каждого обработанного матча. Открытая страница получает обновление через WebSocket, но не чаще раза в 5 секунд.

**Можно ли загрузить новую версию во время турнира?** Да, в рамках правил загрузки выше. Новая версия играет со следующего раунда.

**Куда писать о баге?** В GitHub issues репозитория https://github.com/4RH1T3CT0R7/TJudge. Приложите request-id из заголовка ответа `X-Request-ID`, по нему оператор найдёт запрос в логах.

## Добавление новой игры

Игра — это исполнитель в [tjudge-cli](https://github.com/bmstu-itstech/tjudge-cli) (Rust) и запись в таблице `games`. Кода в Go-сервере под игру нет: воркер передаёт имя игры в tjudge-cli как подкоманду.

1. Поддержка в tjudge-cli: модуль игры, регистрация её имени в CLI, пересборка образа `tjudge-cli` (`make docker-build-executor`).
2. Запись в БД: `POST /api/v1/games` под админом (или вкладка «Игры») с полями `name` (совпадает с именем в tjudge-cli, `[a-z0-9_]+`), `display_name` и `rules` в Markdown. В правилах нужны протокол, формат ввода/вывода и ограничения: участники видят их на странице игры. Альтернатива — seed-миграция по образцу `migrations/000028_seed_new_games.up.sql`.
3. Множитель очков в API не задаётся: по умолчанию 1.0, меняется в БД — `UPDATE games SET score_multiplier = 0.5 WHERE name = 'your_game';`. Подбирается так, чтобы вклад игры в общую таблицу был сопоставим с остальными.
4. Добавить игру к турниру: `POST /api/v1/tournaments/:id/games` с `game_id` в теле (админ или создатель турнира). После этого участники загружают программы и игра входит в раунды.
