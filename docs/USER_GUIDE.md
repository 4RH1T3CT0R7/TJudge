## Введение

**TJudge** — это высоконагруженная турнирная система для проведения соревнований по теории игр. Система позволяет:

- Создавать турниры с различными играми
- Загружать программы-стратегии на любом языке программирования
- Автоматически проводить матчи между программами
- Отслеживать рейтинг в режиме реального времени
- Работать в командах

### Основные возможности

| Возможность | Описание |
|-------------|----------|
| Многопользовательский режим | Регистрация, команды, рейтинги |
| 5 типов игр | Дилемма заключённого, Перетягивание каната, Дилемма путешественника, Общественное благо, Аукцион двойной цены |
| Безопасное выполнение | Изолированные Docker-контейнеры |
| Real-time обновления | WebSocket для таблицы лидеров |
| Автомасштабирование | До 1000 параллельных матчей |

## Быстрый старт

### Требования

- Docker и Docker Compose
- 4GB RAM минимум
- 10GB свободного места на диске

### Запуск системы

```bash
# Клонирование репозитория
git clone https://github.com/bmstu-itstech/tjudge.git
cd tjudge

# Запуск всех сервисов
docker-compose up -d

# Проверка статуса
docker-compose ps
```

| Сервис | URL | Описание |
|--------|-----|----------|
| Веб-интерфейс | http://localhost:8080 | Основной интерфейс |
| Grafana | http://localhost:3000 | Мониторинг (admin/admin) |
| Prometheus | http://localhost:9092 | Метрики |

### Первые шаги

1. Откройте http://localhost:8080
2. Зарегистрируйтесь
3. Перейдите в раздел «Турниры»
4. Присоединитесь к турниру или создайте команду

## Руководство пользователя

### Регистрация и вход

#### Регистрация

1. Перейдите на http://localhost:8080/register
2. Заполните форму:
   - **Имя пользователя** — уникальное, латиницей
   - **Email** — для восстановления пароля
   - **Пароль** — минимум 8 символов
3. Нажмите «Зарегистрироваться»

#### Вход

1. Перейдите на http://localhost:8080/login
2. Введите email и пароль
3. Нажмите «Войти»

> **Важно:** Сессия сохраняется между перезагрузками страницы. При истечении токена потребуется повторный вход.

### Участие в турнирах

#### Просмотр турниров

1. Перейдите в раздел «Турниры»
2. Доступные фильтры:
   - По статусу (Ожидание / Активный / Завершён)
   - По типу

#### Присоединение к турниру

**Способ 1: Создать команду**
1. Откройте страницу турнира
2. Нажмите «Участвовать»
3. Введите название команды
4. Нажмите «Создать»

**Способ 2: Присоединиться по коду**
1. Получите код приглашения от лидера команды
2. Нажмите «Участвовать»
3. Введите код в поле «Код приглашения»
4. Нажмите «Вступить»

#### Управление командой

Если вы лидер команды:

1. Перейдите в «Управление командой»
2. Доступные действия:
   - Скопировать код приглашения
   - Исключить участника
   - Покинуть команду (передаёт лидерство)

### Загрузка программ

#### Требования к программам

- Программа должна читать из **stdin** и писать в **stdout**
- Формат ввода/вывода зависит от типа игры
- Таймаут ответа: **200ms**
- Поддерживаемые языки: Python, C++, Java, Go, Rust, JavaScript

#### Процесс загрузки

1. Откройте страницу игры в турнире
2. Нажмите «Загрузить программу»
3. Выберите файл с кодом
4. Нажмите «Отправить»

#### Статусы программы

| Статус | Описание |
|--------|----------|
| `pending` | Ожидает проверки |
| `compiling` | Компилируется |
| `ready` | Готова к матчам |
| `error` | Ошибка компиляции |

### Просмотр результатов

#### Таблица лидеров

- Обновляется в реальном времени через WebSocket
- Показывает: место, команду, рейтинг, победы/поражения/ничьи
- Кнопка «На весь экран» для проецирования
- Отдельные таблицы для каждой игры турнира

#### История матчей

- Доступна на странице турнира
- Фильтрация по игре, команде, статусу
- Детали каждого матча: счёт, время, ошибки

1. Откройте страницу турнира

**Управление раундами по играм:**

- Статусы: `pending`, `running`, `completed`

## Поддерживаемые игры

В TJudge доступны 5 типов игр. Все они основаны на классических задачах теории игр и предлагают разные стратегические дилеммы: от выбора между сотрудничеством и предательством до управления ресурсами и эскалации конфликта.

Каждая программа-стратегия запускается **один раз** и общается с системой через **stdin/stdout**. Все сообщения -- отдельные строки. Таймаут на каждый ответ: **200ms**.

---

### 1. Дилемма заключённого (Prisoner's Dilemma)

**Идентификатор:** `prisoners_dilemma`
**Тип:** одновременные ходы

#### Описание

Два игрока одновременно выбирают: сотрудничать или предать. Игра повторяется несколько итераций, и программы знают предыдущий выбор соперника, что позволяет строить адаптивные стратегии.

**Стратегическая суть:** взаимное сотрудничество выгоднее взаимного предательства (5 > 1), но предательство против кооператора дает максимум (10). Как поступить, если вы не знаете намерений противника?

#### Правила и таблица выплат

Каждый раунд оба игрока одновременно выбирают одно из двух действий:
- `COOPERATE` -- сотрудничать
- `DEFECT` -- предать

| Вы | Противник | Ваши очки | Очки противника |
|---|---|---|---|
| COOPERATE | COOPERATE | **5** | **5** |
| COOPERATE | DEFECT | 0 | **10** |
| DEFECT | COOPERATE | **10** | 0 |
| DEFECT | DEFECT | 1 | 1 |

#### Протокол взаимодействия

**Инициализация (stdin):** 1 строка -- количество итераций.

```
<количество_итераций>
```

**Каждая итерация:**
1. **Вывод (stdout):** `COOPERATE` или `DEFECT`
2. **Ввод (stdin):** ход противника (`COOPERATE` или `DEFECT`)

**Пример сессии** (стрелка влево -- stdin, стрелка вправо -- stdout):

```
<- 100             # количество итераций
-> COOPERATE       # ваш 1-й ход
<- DEFECT          # противник предал
-> DEFECT          # мстим
<- COOPERATE       # противник сотрудничает
-> COOPERATE       # прощаем
<- COOPERATE
...
```

#### Ограничения

- Допустимые значения: строго `COOPERATE` или `DEFECT` (case-sensitive)
- Другой вывод -- ошибка программы -- **проигрыш матча**
- Таймаут на ответ: **200ms**
- Обязательно сбрасывайте буфер вывода (`flush`) после каждой строки

#### Пример программы (Python)

```python
#!/usr/bin/env python3
"""
Стратегия Tit-for-Tat для Дилеммы заключённого.
Первый ход -- сотрудничаем, далее копируем последний ход противника.
"""

def main():
    iterations = int(input())
    opponent_last = None

    for _ in range(iterations):
        if opponent_last is None or opponent_last == "COOPERATE":
            print("COOPERATE", flush=True)
        else:
            print("DEFECT", flush=True)

        opponent_last = input().strip()

if __name__ == "__main__":
    main()
```

### 2. Перетягивание каната (Tug of War)

**Идентификатор:** `tug_of_war`
**Тип:** одновременные ходы

#### Описание

Игра на управление ресурсами. У каждого игрока есть запас **энергии**. Каждый раунд оба одновременно решают, сколько энергии потратить. Кто потратил больше -- получает очко. Но энергия конечна и не восстанавливается.

**Стратегическая суть:** потратить много сейчас -- значит остаться без сил на последующие раунды. Потратить мало -- значит проиграть текущий раунд. Необходимо балансировать между агрессией и экономией.

#### Правила

- Начальная энергия: **100** единиц у каждого
- Каждый раунд оба игрока одновременно тратят от 0 до оставшейся энергии
- Кто потратил **больше** -- получает **1 очко**
- Равная трата -- **0 / 0**
- Энергия **не восстанавливается** между раундами
- Нельзя потратить больше, чем осталось

| Вы потратили | Противник потратил | Ваши очки | Очки противника |
|---|---|---|---|
| 30 | 20 | **1** | 0 |
| 20 | 30 | 0 | **1** |
| 25 | 25 | 0 | 0 |

#### Протокол взаимодействия

**Инициализация (stdin):** 2 строки -- начальная энергия и количество итераций.

```
<начальная_энергия>
<количество_итераций>
```

**Каждая итерация:**
1. **Вывод (stdout):** целое число -- сколько энергии потратить (от 0 до остатка)
2. **Ввод (stdin):** сколько потратил противник (целое число)

**Пример сессии:**

```
<- 100            # начальная энергия
<- 10             # количество итераций
-> 30             # тратим 30 (осталось 70)
<- 20             # противник потратил 20 -> мы +1
-> 25             # тратим 25 (осталось 45)
<- 25             # равно -> 0/0
-> 10             # тратим 10 (осталось 35)
<- 40             # противник потратил 40 -> он +1
...
```

#### Ограничения

- Трата должна быть целым числом от 0 до оставшейся энергии
- Превышение остатка -- ошибка программы -- **проигрыш матча**
- Нечисловой вывод -- ошибка -- проигрыш
- Таймаут на ответ: **200ms**
- Обязательно сбрасывайте буфер вывода (`flush`) после каждой строки

#### Пример программы (Python)

```python
#!/usr/bin/env python3
"""
Консервативная стратегия для Перетягивания каната.
Тратим 10% от оставшейся энергии каждый раунд.
"""

def main():
    energy = int(input())       # начальная энергия
    iterations = int(input())   # количество итераций

    for _ in range(iterations):
        spend = max(1, energy // 10) if energy > 0 else 0
        print(spend, flush=True)

        opponent_spent = int(input())
        energy -= spend

if __name__ == "__main__":
    main()
```

### 3. Дилемма путешественника (Traveler's Dilemma)

**Идентификатор:** `travelers_dilemma`
**Тип:** одновременные ходы

#### Описание

Два путешественника потеряли одинаковые чемоданы. Авиакомпания просит каждого **независимо** назвать стоимость. Хитрость: если значения отличаются, оба получают **меньшее** из двух, но назвавший меньше получает бонус, а назвавший больше -- штраф.

**Стратегическая суть:** равновесие Нэша предписывает обоим называть минимум (L=2), но кооперативные стратегии с высокими заявками (~90) часто побеждают в турнире. Парадокс рациональности: формально оптимальная стратегия проигрывает практически.

#### Правила подсчета

- Оба назвали **одинаковое** число -- оба получают это число
- Числа **различаются** -- оба получают **min** из двух значений, при этом:
  - Назвавший **меньше**: **+R** (бонус)
  - Назвавший **больше**: **-R** (штраф)

Параметры по умолчанию: L=2 (нижняя граница), U=100 (верхняя граница), R=2 (бонус/штраф).

| Вы | Противник | Ваши очки | Очки противника |
|---|---|---|---|
| 50 | 50 | 50 | 50 |
| 30 | 70 | 30+R = **32** | 30-R = **28** |
| 80 | 40 | 40-R = **38** | 40+R = **42** |
| 2 | 2 | 2 | 2 |

#### Протокол взаимодействия

**Инициализация (stdin):** 4 строки.

```
<L>              # нижняя граница (по умолчанию 2)
<U>              # верхняя граница (по умолчанию 100)
<R>              # бонус/штраф (по умолчанию 2)
<итерации>       # количество итераций
```

**Каждая итерация:**
1. **Вывод (stdout):** целое число в диапазоне [L, U] -- ваша заявка
2. **Ввод (stdin):** заявка противника (целое число)

**Пример сессии:**

```
<- 2              # L
<- 100            # U
<- 2              # R
<- 100            # количество итераций
-> 85             # ваша заявка
<- 90             # заявка противника -> вы: 85+2=87, он: 85-2=83
-> 80
<- 75             # -> вы: 75-2=73, он: 75+2=77
...
```

#### Ограничения

- Заявка должна быть целым числом в диапазоне [L, U]
- Выход за границы -- ошибка программы -- **проигрыш матча**
- Таймаут на ответ: **200ms**
- Обязательно сбрасывайте буфер вывода (`flush`) после каждой строки

#### Пример программы (Python)

```python
#!/usr/bin/env python3
"""
Стратегия «адаптивный кооператор» для Дилеммы путешественника.
Начинаем с высокой заявки и подстраиваемся под противника.
"""

def main():
    L = int(input())
    U = int(input())
    R = int(input())
    iterations = int(input())

    my_claim = U  # начинаем с максимума

    for _ in range(iterations):
        print(my_claim, flush=True)
        opponent_claim = int(input())

        # Подстраиваемся: среднее между нашей и заявкой противника
        my_claim = max(L, min(U, (my_claim + opponent_claim) // 2))

if __name__ == "__main__":
    main()
```

### 4. Общественное благо (Public Goods Game)

**Идентификатор:** `public_goods`
**Тип:** одновременные ходы

#### Описание

У каждого игрока в начале каждой итерации есть **E** токенов. Оба одновременно решают, сколько вложить в общий пул. Пул умножается на коэффициент и делится поровну. Невложенные токены остаются.

**Стратегическая суть:** дилемма безбилетника. Если оба вкладывают все -- каждый получает по 30 (при E=20, m=1.5). Если никто не вкладывает -- по 20. Но если один вложит все, а другой ничего -- жадный получит 35. Как в жизни: общественные блага создаются вкладом каждого, но велик соблазн не участвовать.

#### Формула выплаты

```
Выплата = (E - ваш_вклад) + m * (вклад_1 + вклад_2) / 2
```

Результат усекается до целого числа.

Параметры по умолчанию: E=20 (начальный капитал), m=1.5 (множитель пула).

#### Примеры (E=20, m=1.5)

| Вы вложили | Противник вложил | Ваши очки | Очки противника | Комментарий |
|---|---|---|---|---|
| 20 | 20 | **30** | **30** | Оба вложили все: 0 + 1.5*40/2 |
| 0 | 0 | **20** | **20** | Никто не вложил |
| 0 | 20 | **35** | **15** | Безбилетник выигрывает |
| 10 | 10 | **25** | **25** | Частичный вклад |

#### Протокол взаимодействия

**Инициализация (stdin):** 3 строки.

```
<E>              # начальный капитал (по умолчанию 20)
<m>              # множитель, дробное число (по умолчанию 1.5)
<итерации>       # количество итераций
```

**Каждая итерация:**
1. **Вывод (stdout):** целое число в диапазоне [0, E] -- ваш вклад
2. **Ввод (stdin):** вклад противника (целое число)

**Пример сессии:**

```
<- 20             # E
<- 1.5            # m
<- 100            # количество итераций
-> 15             # ваш вклад
<- 10             # вклад противника -> пул = 1.5*(15+10)/2 = 18.75
-> 20
<- 0              # -> вы: 0+15=15, он: 20+15=35
...
```

#### Ограничения

- Вклад должен быть целым числом в диапазоне [0, E]
- Превышение E -- ошибка программы -- **проигрыш матча**
- Таймаут на ответ: **200ms**
- Обязательно сбрасывайте буфер вывода (`flush`) после каждой строки

#### Пример программы (Python)

```python
#!/usr/bin/env python3
"""
Стратегия «зеркальный вкладчик» для Общественного блага.
Начинаем с полного вклада, далее копируем противника.
"""

def main():
    E = int(input())
    m = float(input())
    iterations = int(input())

    my_invest = E  # начинаем с полного вклада

    for _ in range(iterations):
        print(my_invest, flush=True)
        opponent_invest = int(input())

        # Копируем вклад противника на следующий раунд
        my_invest = max(0, min(E, opponent_invest))

if __name__ == "__main__":
    main()
```

### 5. Аукцион двойной цены (Dollar Auction)

**Идентификатор:** `dollar_auction`
**Тип:** поочередные ходы

#### Описание

На торги выставляется приз стоимостью **P**. Игроки **поочередно** делают ставки. Ключевое правило: **оба** платят свои последние ставки, но приз получает только победитель.

**Стратегическая суть:** ловушка эскалации (сunk cost fallacy). Когда вы уже вложили много, кажется выгоднее повысить ставку, чем потерять вложенное. Но противник рассуждает так же -- ставки могут **превысить стоимость приза**, и оба окажутся в минусе. Единственная поочередная игра в системе.

#### Правила торгов

1. Игроки ходят **по очереди** (первый игрок начинает)
2. Каждая ставка должна быть **строго больше** последней ставки противника
3. Ставка **0** = пас -- торги заканчиваются
4. Торги также заканчиваются при исчерпании раундов

#### Подсчет очков

- **Победитель** (чья ставка выше): `приз - своя_ставка`
- **Проигравший**: `-своя_ставка`
- Оба спасовали: **0 / 0**

| Ход | Ставки | Результат |
|---|---|---|
| П1 пасует | -- | 0, 0 |
| П1: 1, П2: пас | 1 vs 0 | П1: **99**, П2: 0 |
| П1: 1, П2: 2, П1: 3, П2: пас | 3 vs 2 | П1: **97**, П2: **-2** |
| П1: 50, П2: 60, П1: 70, П2: пас | 70 vs 60 | П1: **30**, П2: **-60** |
| П1: 80, П2: 90, П1: 110, П2: пас | 110 vs 90 | П1: **-10**, П2: **-90** |

#### Протокол взаимодействия

**Инициализация (stdin):** 2 строки.

```
<P>              # стоимость приза (по умолчанию 100)
<макс_раундов>   # максимальное количество раундов
```

**Каждый ход** (игроки ходят по очереди):
1. **Ввод (stdin):** последняя ставка противника (0 в начале торгов)
2. **Вывод (stdout):** ваша ставка -- целое число **строго больше** ставки противника, или **0** чтобы спасовать

> **Важно:** в отличие от остальных игр, здесь сначала приходит ход противника, потом вы отвечаете.

**Пример сессии:**

```
<- 100            # приз
<- 50             # макс. раундов
<- 0              # ставка противника (торги начались)
-> 10             # ваша ставка
<- 15             # противник повысил
-> 20             # повышаем
<- 0              # противник спасовал -> вы победили: 100-20=80, он: -15
```

#### Ограничения

- Ставка >= 0; если > 0, то строго больше последней ставки противника
- Нарушение -- ошибка программы -- **проигрыш матча**
- Это **поочередная** игра (в отличие от остальных, где ходы одновременные)
- Таймаут на ответ: **200ms**
- Обязательно сбрасывайте буфер вывода (`flush`) после каждой строки

#### Пример программы (Python)

```python
#!/usr/bin/env python3
"""
Стратегия «осторожный торговец» для Аукциона двойной цены.
Делаем ставку только если потенциальная прибыль положительна.
"""

def main():
    P = int(input())
    max_rounds = int(input())

    for _ in range(max_rounds):
        opponent_bid = int(input())

        if opponent_bid == 0 and _ == 0:
            # Торги начались, ставим минимум
            print(1, flush=True)
        elif P - (opponent_bid + 1) > 0:
            # Повышаем на 1, если прибыль остается положительной
            print(opponent_bid + 1, flush=True)
        else:
            # Невыгодно продолжать -- пасуем
            print(0, flush=True)
            break

if __name__ == "__main__":
    main()
```

## Написание программ-стратегий

### Общие требования

1. **Ввод/вывод:** stdin/stdout (одна строка = одно сообщение)
2. **Таймаут:** 200ms на каждую операцию ввода-вывода
3. **Память:** до 256MB
4. **Процессы:** до 32
5. **Flush:** обязательно сбрасывайте буфер после каждого вывода

### Поддерживаемые языки

| Язык | Расширение | Запуск |

| JavaScript | `.js` | `node program.js` |
| Rust | `.rs` | Компиляция + запуск |

### Шаблон программы (Дилемма заключённого)

```python
#!/usr/bin/env python3
"""
Шаблон: Tit-for-Tat для Дилеммы заключённого.
Программа запускается один раз, общается через stdin/stdout.

Протокол:
  - Инициализация: 1 строка (количество итераций)
  - Каждая итерация: вывод COOPERATE/DEFECT, ввод хода противника
"""

def main():
    iterations = int(input())  # инициализация: кол-во итераций
    opponent_last = None

    for _ in range(iterations):
        # Стратегия: первый ход -- сотрудничаем, далее копируем противника
        if opponent_last is None or opponent_last == "COOPERATE":
            print("COOPERATE", flush=True)
        else:
            print("DEFECT", flush=True)

        opponent_last = input().strip()  # получаем ход противника

if __name__ == "__main__":
    main()
```

> Шаблоны для остальных 4 игр приведены в разделе [Поддерживаемые игры](#поддерживаемые-игры).

### Советы по написанию

1. **Всегда используйте `flush=True`** при выводе (или `sys.stdout.flush()`)
2. **Обрабатывайте EOFError** для корректного завершения
3. **Не используйте сеть** — она заблокирована
4. **Не пишите в файлы** — доступ ограничен
5. **Тестируйте локально** перед загрузкой
6. **Таймаут 200ms** на каждую операцию — оптимизируйте алгоритмы

## TJudge CLI

### Описание

**tjudge-cli** — это Rust-приложение для запуска матчей между программами. Оно используется внутри Docker-контейнеров системой TJudge.

### Исходный код

Репозиторий: https://github.com/bmstu-itstech/tjudge-cli

### Сборка образа

```bash
# Сборка Docker-образа с tjudge-cli
make docker-build-executor

# Или напрямую
docker build -t tjudge-cli:latest -f docker/tjudge/Dockerfile .
```

### Использование

```bash
tjudge-cli <GAME_TYPE> [OPTIONS] <PROGRAM1> <PROGRAM2>
```

#### Аргументы

| Аргумент | Описание |
|----------|----------|
| `GAME_TYPE` | Тип игры: `prisoners_dilemma`, `tug_of_war`, `travelers_dilemma`, `public_goods`, `dollar_auction` |
| `PROGRAM1` | Путь к первой программе |
| `PROGRAM2` | Путь к второй программе |

#### Опции

| Опция | Описание | По умолчанию |
|-------|----------|--------------|
| `-i, --iterations N` | Количество раундов | 1000 |
| `-v, --verbose` | Подробный вывод | выкл |

#### Примеры

```bash
# Базовый запуск
tjudge-cli prisoners_dilemma program1.py program2.py

tjudge-cli prisoners_dilemma -i 500 program1.py program2.py

tjudge-cli prisoners_dilemma -v -i 100 program1.py program2.py
```

### Выходные данные

**Успешное завершение (код 0):**

**Коды ошибок:**

## Архитектура системы

### Компоненты

```
┌─────────────────────────────────────────────────────────────────┐
│                         Web Browser                              │
│                    (React SPA @ :8080)                          │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                         API Server                               │
│                    (Go Chi @ :8080)                             │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐          │
│  │   Auth   │ │Tournament│ │  Match   │ │ WebSocket│          │
│  │ Handler  │ │ Handler  │ │ Handler  │ │ Handler  │          │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘          │
└─────────────────────────────────────────────────────────────────┘
         │                         │                    │
         ▼                         ▼                    ▼
┌─────────────┐           ┌─────────────┐      ┌─────────────┐
│  PostgreSQL │           │    Redis    │      │   Worker    │
│   (Data)    │           │(Cache/Queue)│      │    Pool     │
└─────────────┘           └─────────────┘      └─────────────┘
                                                      │
                                                      ▼
                                            ┌─────────────────┐
                                            │ Docker Executor │
                                            │  (tjudge-cli)   │
                                            └─────────────────┘
```

### Поток обработки матча

```
1. POST /api/v1/tournaments/{id}/matches
              │
              ▼
2. Создание Match (status: pending)
              │
              ▼
3. Добавление в Redis Queue (priority: high/medium/low)
              │
              ▼
4. Worker берёт из очереди
              │
              ▼
5. Обновление status → running
              │
              ▼
6. Запуск Docker контейнера с tjudge-cli
              │
              ▼
7. Парсинг результата
              │
              ▼
8. Обновление status → completed/failed
              │
              ▼
9. Обновление рейтингов (ELO)
              │
              ▼
10. WebSocket уведомление клиентам
```

### Очередь с приоритетами

```
queue:high   ──► [Матчи высокого приоритета]  ──┐
queue:medium ──► [Матчи среднего приоритета] ──┼──► Worker Pool
queue:low    ──► [Матчи низкого приоритета]  ──┘
```

Воркеры сначала берут из `high`, затем `medium`, затем `low`.

### Автомасштабирование воркеров

| Размер очереди | Действие |
|----------------|----------|
| > 100 задач | +10 воркеров |
| > 50 задач | +5 воркеров |
| < 10 задач и >50% простаивают | -5 воркеров |

Диапазон: 2 – 100+ воркеров (настраивается через переменные окружения).

## Устранение неполадок

### Программа не запускается

**Симптом:** Статус программы `error`

**Решения:**
1. Проверьте shebang (`#!/usr/bin/env python3`)
2. Убедитесь, что файл читает из stdin
3. Проверьте синтаксис локально

### Таймаут при выполнении

**Симптом:** Матч завершается с ошибкой таймаута

**Решения:**
1. Оптимизируйте алгоритм
2. Используйте `flush=True` при выводе
3. Не используйте бесконечные циклы

### WebSocket не подключается

**Симптом:** Ошибка 401 при подключении

**Решения:**
1. Перелогиньтесь (токен мог истечь)
2. Проверьте, что токен передаётся в query-параметре

### Матчи не обрабатываются

**Симптом:** Матчи застряли в статусе `pending`

**Решения:**
```bash
# Проверьте воркеры
docker-compose logs worker

# Перезапустите воркеры
docker-compose restart worker

# Проверьте очередь Redis
docker exec tjudge-redis redis-cli LLEN queue:high
```

### База данных недоступна

**Симптом:** Ошибки подключения к PostgreSQL

**Решения:**
```bash
# Проверьте статус
docker-compose ps postgres

# Проверьте логи
docker-compose logs postgres

# Перезапустите
docker-compose restart postgres
```
